# SkillYard Library 两主题 UI 规范

本文档把两张已确认参考图转换为可研发、可比较、可验收的前端规范。参考图是高置信视觉依据，但不是唯一真值；产品行为仍以现有 `InventoryPage`、统一 Bundle read model 和生命周期回调为准。

设计理解同时纳入 Codex 任务 `019ff3f0-3199-7120-9f33-8bf5888bc98d` 中 Product Design 生成的内容 1 与内容 2：内容 1（`exec-f0da0df5-ca2e-4e05-854a-68950d3e3f04`）用于校准 Layers 的纸张层级、单一阅读基线与成员信息密度，内容 2（`exec-66eeb866-059e-47ba-a844-e9d3081b350a`）用于校准 Ledger 的扫描效率、资料带和语义成员表。它们是设计解释依据，不新增第三个主题，也不覆盖真实产品状态、可用性或可访问性要求；仓库仍只维护下列两张主题参考图。

## 2. 共享产品合同

两套主题共享：

- 同一份 Bundle 列表、选中 Bundle、搜索词、管理状态筛选、分类筛选和排序状态；
- 排序只提供现有真值能够支持的“管理状态优先”和“名称 A–Z”，切换主题时保持当前模式与选中 Bundle；参考图中的“按最近使用排序”没有访问时间真值，不得用安装、扫描、更新或当前选择时间冒充；
- 同一套 `查看 Bundle`、安装、发现、项目、设置、更新、刷新、挂载、接管和删除回调；
- 同一个 Agent Session 和浮动入口；
- 同一组可访问名称、键盘选择行为和确认流程。

两套主题可以不同：

- 顶部导航的视觉结构；
- Bundle 列表的陈列方式；
- 当前 Bundle 详情的布局；
- 纯展示用的横向位置、层叠方式和装饰资产。

不得为任一主题复制领域状态、生命周期入口或持久化协议。

### 通用尺寸

- 默认窗口：`1180 × 840`。
- 顶部导航交互高度：`38–44px`。
- 普通 UI 正文：`13–15px`，行高 `1.45–1.65`。
- 次要信息：`11–12px`。
- 主按钮圆角：`8–10px`；浮层圆角：`14–18px`。

## 7. 窗口适配边界

- 两套主题共享 `reference` 与 `compact` 两种布局状态；状态只由当前可见窗口尺寸决定，不进入领域模型、偏好或主题持久化。
- 当 `min(窗口宽 / 1180, 窗口高 / 840) >= 0.9` 时使用 `reference`：维持同一个 `1180 × 840` 坐标系，页面、浮层和 Agent 入口统一缩放并居中，不能拉伸任一方向。
- 比例低于 `0.9` 时使用 `compact`：画布直接匹配可见窗口，Ledger 收紧主从栏，Layers 收紧书脊与纸张；两者继续复用同一导航、状态、动作和详情组件，不新建移动路由或第二套 renderer。
- 正式最小窗口为 `760 × 560`；在该尺寸下普通正文保持至少 `12px`，主要顶栏与表单控件保持约 `40px` 高，设置页、详情纸张和详情栏可以在各自唯一正文区域纵向滚动。
- 内容超长时优先截断顶栏搜索、次要元数据和成员预览；完整内容继续由详情页读取，不通过继续缩小整张画布解决，也不得叠加多个相互竞争的文档滚动区。
- `<760px` 不属于 1.1.0 的正式窗口范围；Tauri `minWidth` 继续限制为 `760px`。

## 8. 验收方法

验收分为两个互补层级，不能用反复重建 VM 代替本地设计闭环：

1. 本地确定性夹具通过现有 `App` 与 typed Tauri client seam 注入同一份五 Bundle、`200` Skill、`91` 个健康 Mount 状态；它不新增生产路由、领域模型或生命周期入口。
2. 本地一次覆盖 Ledger/Layers、`1180 × 840` reference、`760 × 560` compact、排序保持、键盘选择、设置滚动、主题切换和 Agent 开合；截图必须与对应参考图放在同一次比较输入中判断。
3. 行为测试、typecheck、全量前端测试、Rust 测试、`clippy -D warnings` 和生产构建全部通过后，冻结同一个候选 `.app` 与 SHA-256。
4. 只有冻结候选后才运行至多一次 Tart 冒烟；VM 只确认真实 WebView、原生窗口边界、生产 bundle、主题状态保持和两种布局尺寸，不再承担夹具构造、像素迭代或重复探索。Keychain、真实 Provider、API Key、连接测试、AI 整理和真实 Agent 请求属于独立产品验收，不进入本轮视觉 Tart。
5. 任一层级发现 P0、P1 或 P2 时回到本地修复并重新冻结候选；旧 VM 证据立即失效，不通过连续申请相似危险操作在同一候选上重试。
6. 只有剩余有明确依据的 P3 视觉差异时才可通过；参考图与真实状态、可读性或可访问性冲突时记录采用产品质量的理由。
