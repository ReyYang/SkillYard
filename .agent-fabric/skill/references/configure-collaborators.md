# 发现与配置协作者

目标是让用户看见当前环境真正可用的选择，并把用户采用的 Role 绑定保存为本机真值。发现、验证和采用是三个不同阶段。

## 1. 静态发现

根据当前环境的真实证据寻找：

- 当前 Agent 自带的委派、浏览或连接能力；
- 有可信安装或包信息支持的本机 Agent CLI；
- 当前可用的网页 Agent、浏览器或连接器；
- 用户主动提供的其他工具。

用普通语言展示可能承担的 Role、已知能力和证据状态。只列出有实际依据的候选，不倾倒整个 `PATH`，也不使用固定产品白名单。此阶段保持只读，不运行候选命令、不登录、不联网，也不读取凭据。

完成条件：每个展示的候选都有来源证据和清楚的“已发现、尚未验证或可用”状态；无关程序没有混入选择列表。

## 2. 推荐 Role 绑定

`orchestrator` 始终是用户正在直接使用的当前 Agent，不需要绑定。为其他 Role 推荐协作者时说明依据：

- `implementer`：能否承担完整实现和本地技术判断；
- `worker`：能否稳定完成边界明确的窄任务；
- `researcher`：能否只读收集所需证据并标明来源边界；
- `reviewer`：能否检查真实结果，以及与执行者的独立程度。

同时说明模型、调用方式、可用状态、权限、成本或其他会影响选择的事实。只有用户采用后才形成绑定；更换协作者不修改 Role。

完成条件：用户能看懂每个推荐的理由、限制和审查独立性，并明确选择采用、跳过或稍后处理。

## 3. 经许可验证

只有静态证据不足且用户希望继续时，才验证候选。运行前展示准确操作及其副作用：

- `--help`、版本或兼容性 probe：展示准确命令；
- 登录、联网、真实任务、安装或项目外配置修改：分别说明并取得对应许可；
- 缺少外部工具：跳过并说明用户可自行安装的内容，不自动安装。

自由文本或 Markdown 输出可以构成有效证据，不要求候选返回固定 JSON。验证失败保留原失败状态，不尝试未获用户选择的替代品。

完成条件：所有实际执行都有匹配的许可和可解释结果；没有候选因发现过程而获得额外权限或被自动安装。

## 4. 保存本机真值

把用户采用的配置写入 `.agent-fabric/local/resolution.json`。对每个已绑定 Role，记录足以让后续 Agent 理解和复核的内容：协作者、模型、调用方式、当前可用状态，以及必要的独立性或验证说明。

该文件保持可扩展：保留当前环境需要的额外字段，不强制产品、连接类型或模型枚举。需要复现本机兼容性探测时，可以在 `.agent-fabric/local/adapters/` 保存最小连接说明；它不是 Portable Catalog，也不是日常调用中间层。

完成条件：配置反映用户刚刚选择的真实绑定；未知字段和未涉及 Role 得到保留；不可用项没有被写成可用，也没有 silent fallback。

## 5. 投影并说明使用方式

优先在项目内创建当前宿主支持的 Skill 投影，使它指向 `.agent-fabric/skill/SKILL.md`。投影是可重建派生物，不是第二真值。项目外或全局配置只有在用户精确批准后才可修改。

宿主没有项目内 Skill 机制时，告诉用户直接显式要求 Agent 读取 `.agent-fabric/skill/SKILL.md`。宿主不能保证只由用户调用时，明确报告该限制。

完成条件：用户知道当前绑定、缺失工具、Skill 的实际调用方式和需要自行完成的安装；写入仅发生在已批准范围内。
