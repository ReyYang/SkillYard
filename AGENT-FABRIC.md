# Agent Fabric 可移植蓝图

版本：`1.0.0-rc.4`

这是一个可以交给任意具备文件读写能力的 Agent 的单文件蓝图。它不属于某个 Agent 产品，也不指定必须使用哪一种 CLI、网页 Agent、模型或 provider。

## 这套框架是做什么的

Agent Fabric 在普通项目里增加一套可选择启用的多 Agent 协作方式：

- 用户正在直接使用的当前 Agent 始终承担 `orchestrator`，负责理解目标、保留权限、选择协作者、综合结果和最终交付。
- `implementer`、`worker`、`researcher`、`reviewer` 是稳定 Role；它们描述协作责任，不绑定具体 Agent 或模型。
- 当前电脑实际有哪些 Agent CLI、网页 Agent、浏览器、连接器或原生委派能力，由初始化 Agent 在当地发现，并由用户选择怎样绑定。
- 日常协作只有在用户明确调用 Agent Fabric Skill 时发生。普通任务不会因为项目里有这个目录就自动变成多 Agent 任务。
- Rust 只是可选的初始化、检查、修复、兼容性探测和验收工具，不参与日常协作。

这个文件的目标是让你换项目、换电脑或换当前 Agent 后，仍能从同一份蓝图恢复相同的框架结构和协作含义。

## 把本文件交给 Agent 后会发生什么

初始化 Agent 应先做只读说明和发现，不应立刻写文件：

1. 用普通语言说明 Agent Fabric 的用途、日常调用方式和安全边界。
2. 确认目标项目根的规范化绝对路径；Git 不是必需条件。
3. 使用静态、非侵入式证据发现当前 Agent 自带能力、本机可能的 Agent CLI、网页或浏览能力、连接器以及用户提供的工具。
4. 只展示有实际证据支持的高价值选项，说明哪些只是“已发现、尚未验证”，并帮助用户为各 Role 选择协作者和模型。
5. 展示将创建的项目内文件、当前已有冲突、是否能构建 Rust 维护工具，以及是否能创建当前宿主的项目内 Skill 投影。
6. 在运行候选命令、probe、登录、联网、安装、写项目外配置或执行真实任务前，分别取得相应许可。

静态发现不能借机运行未知命令，也不应把整个 `PATH` 或内部分类术语倾倒给用户。不存在固定工具白名单；初始化 Agent 根据当前环境的真实证据判断。

## 用户确认后，init 会做什么

用户逐字确认目标项目根后，初始化 Agent：

1. 校验本文件机器附录中的文件路径、内容与 hash，确保全部内容可恢复后再写入。
2. 在目标根创建 `.agent-fabric/` 的通用 Markdown、Role、Skill、Rust 源码和脚本；不在 `.agent-fabric/` 里再次创建 Agent Fabric。
3. 创建或更新 `.agent-fabric/local/resolution.json`，记录当前机器实际采用的 Role、协作者、模型和调用方式。它是本机配置的唯一真值。
4. 如果当前宿主支持项目内 Skill，生成一个指向 `.agent-fabric/skill/SKILL.md` 的可重建投影，并在 `resolution.json` 记录结果；不得把宿主专有格式反写进本蓝图。
5. 如果存在兼容的 `rustc`，离线构建维护 binary 并运行结构验证；如果没有，则跳过 binary，明确说明维护工具暂不可用。
6. 汇报实际创建内容、已选择的协作者、审查是否独立，以及仍未验证的外部能力。

`init` 不自动运行外部 Agent，不自动安装或登录，不修改项目外全局配置，也不执行任何 Git 操作。已有未知文件或用户修改不得被覆盖。

## 初始化后的最简单用法

日常使用时直接对当前 Agent 说：

> 请显式使用项目里的 Agent Fabric，帮我完成这个任务：……

如果当前宿主没有识别 Skill 投影，说：

> 请读取 `.agent-fabric/skill/SKILL.md`，并按其中的协作流程完成这个任务：……

查看或更换协作者时说：

> 请使用 Agent Fabric 查看并重新配置本项目的协作者。

日常 Skill 会按需读取 Role 和本机 `resolution.json`，然后直接使用当前宿主真实提供的委派、CLI、浏览器或其他工具。它不会调用 Rust、`agent-run` 或中央调度程序。

## 没有 Rust、外部 Agent 或 Git 时

- **没有 `rustc`**：仍然完整创建 Markdown、Role、Skill、源码和本机配置；只跳过维护 binary。用户安装 Rust 后可运行 `.agent-fabric/bin/build-runtime`。
- **没有外部 Agent**：框架仍可由当前 Agent 单独使用；没有独立 Reviewer 时必须明确写“自审”，不能伪称独立审查。
- **不是 Git 项目**：完全支持。写入前仍要逐字确认目标根；框架不会创建 `.git` 或执行 Git 命令。

## 协作者发现与配置

本蓝图不列出任何固定 Agent 工具。初始化 Agent 和后续 Skill 应发现当前环境真正存在的能力，并向用户展示：

- 当前 Agent 自带、且可以直接使用的能力；
- 有静态证据支持的本机 Agent CLI；
- 当前环境可使用的网页 Agent、浏览器或连接器；
- 用户主动提供的其他工具。

只有用户选择后，才把具体协作者、模型和调用方式写入 `.agent-fabric/local/resolution.json`。更换协作者只修改本机配置，不修改 Role。协作者不可用时明确报告，禁止 silent fallback。

## 协作内容与留存

`contracts/` 只建议 Task、Result 和 Review 可以包含哪些有用信息，不规定固定字段、标题、顺序、字数或 JSON。当前 Agent 按语义理解自由格式结果，必要时补充背景或追问。

外部协作默认是临时的：

- 成功但未采用：丢弃临时内容。
- 被当前 Agent 正式采纳为重要证据或用户要求保留：整理后写入 `records/<task-id>/`，并告诉用户保留了什么。
- 失败或需要排错：把必要材料写入 `local/traces/<run-id>/`，默认不进入 Git。

默认不保存完整对话、凭据或可能敏感的原始内容。网页或远端服务可能自行保留会话，当前 Agent 必须把远端留存与项目内留存分开说明。

## 不能越过的边界

- 写入前确认准确项目根，只管理该项目内的框架文件。
- 不覆盖未知文件或用户修改，不穿过 symlink 写入项目外路径。
- 运行外部工具、安装、登录、联网或修改全局配置前说明并取得相应许可。
- 不静默更换协作者、模型、provider、调用方式或权限。
- 不把同一 Agent、同一模型或未隔离上下文的检查伪称独立审查。
- `init`、`check`、`verify` 和 `repair` 不执行 Git 操作。

## 给初始化 Agent 的恢复要求

正文定义产品行为；下面的机器附录只提供确定性文件内容，不能增加正文没有说明的产品限制。

恢复时：

1. 只解析唯一机器块，先校验整体校验值、每个相对路径、文件内容和 SHA-256。
2. 不依赖 Rust 也可以直接创建清单中的文件；先完成全部校验和冲突预览，再经用户逐字确认根后写入。
3. `local/resolution.json` 和宿主 Skill 投影属于当前机器派生配置，由初始化 Agent 根据真实发现和用户选择生成，不写回机器附录。
4. 有兼容 `rustc` 时才构建维护程序；缺失时 init 仍成功，维护能力单独报告为不可用。
5. 完成后验证 Skill、Role、协作参考、受管文件和本机配置都可读；不要求绑定所有 Role，也不执行外部候选。
